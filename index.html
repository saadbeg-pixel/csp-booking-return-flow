Partner App · Booking flow · Design update

Coming back to an accepted booking

Once a partner has accepted a booking, every way back into it leads to the same place: the installation-day screen. Going back from that screen shows the booking card in an Accepted version, with new CTAs. Nothing in this flow undoes the acceptance.

At a glance

What changes

01 · Re-entry

Card tap opens the day screen

If the partner leaves the installation-day screen and later taps the booking on Home, the same day screen opens.

02 · Back

Back shows the Accepted card

Back from the day screen opens the booking card in its Accepted version. The booking stays accepted.

03 · CTAs

New CTAs on the card

इंस्टालेशन का दिन देखें and कनेक्शन नहीं लगा सकता replace accept/decline. The ✕ closes without a sheet.

Flows

The two journeys

Flow 1 · Leave the day screen, come back from Home

Booking accepted→ Day screen→ Partner leaves (✕ / back / app closed)→ Home→ Taps the same booking card→ Same day screen

Flow 2 · Back from the day screen

Day screen→ ← Booking card · Accepted version

From the Accepted card, there are three ways out:

Primary CTA

इंस्टालेशन का दिन देखें →

Opens the day screen again.

Tertiary CTA

कनेक्शन नहीं लगा सकता

Starts the post-acceptance cancel flow, same as today: day-change offer → still cancel → rejection reasons → each reason's own flow.

✕ close

Close directly

No bottom sheet. Return to where the partner came from (Home, in the normal case).

The state does not change. Going back from the day screen is just navigation. It makes no API call, the booking stays Accepted (AWAITING_TECHNICIAN_ASSIGNMENT, acceptanceReceived = true), and the partner never sees the accept/decline CTAs for it again.

Screen

Booking card · Accepted version

The card itself (map, ₹750 banner, landmark, address, audio, पता नहीं समझ आया ?) is identical to the version before acceptance. Only the bottom CTA bar and the ✕ behave differently.

When to show it

  • Show it only when the partner presses back on the day screen and the booking is accepted with no team assigned yet (acceptanceReceived = true, executor = null).
  • Tapping the booking card on Home never opens this version. That always opens the day screen (Flow 1).

Post-acceptance cancel flow (reused as is)

The tertiary CTA calls the same entry point as नहीं कर पाएँगे on the day screen (BookingViewModel.requestExit()), so both cohorts behave exactly as they do today:

  • Rollout: यह काम छोड़ रहे हैं? (day-change nudge) → फिर भी छोड़ना है → rejection reasons → each reason's own flow.
  • Legacy: free date-change reminder (if changes are left) → quality warning → exit reasons.
  • Picking “change day” at the nudge opens the day-change flow, just like from the day screen.

For build

Where the change sits

  • Routing from Home: TaskDrilldownScreen decides whether a booking enters BookingFlowContent. Accepted, team-pending installs should always enter it, so they land on BookingDateScreen.
  • Back from the day screen: BookingDateScreen's ← and system back go to the Accepted card, not Home. This is in-screen state on the same drilldown route, not a new nav destination. Make sure system back isn't caught first by the route-level BackHandler.
  • Accepted card: reuse BookingFpnOverlay with an accepted mode. It swaps the two CTAs, and in that mode the ✕ and system back close directly with no BookingDismissSheet.
  • Tertiary CTA: bookingVm.requestExit(), the same call the day screen's नहीं कर पाएँगे makes.
  • No state writes: none of the navigation above calls an API or changes the task state.
